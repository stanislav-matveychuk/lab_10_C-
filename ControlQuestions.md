# Відповіді на контрольні питання

1. Багатошарова архітектура розділяє програму на рівні з окремими обов'язками.
2. Основні рівні: Presentation, Application/BLL, Infrastructure/DAL, Domain.
3. Presentation приймає запити користувача та повертає відповіді.
4. BLL реалізує правила й сценарії роботи, наприклад перевірку зайнятості лікаря.
5. DAL читає та зберігає дані у сховищі.
6. Domain містить сутності предметної області та контракти репозиторіїв.
7. Переваги: модульність, підтримуваність, заміна компонентів, тестованість.
8. Недоліки: більше класів, складніші залежності та додаткові виклики між шарами.
9. Шари можна тестувати окремо, замінюючи залежності тестовими реалізаціями.
10. Кожен шар розміщується в окремому проєкті, API збирає залежності разом.
11. BLL визначає, що потрібно робити; DAL визначає, як зберігати й отримувати дані.
12. Репозиторій приховує конкретний механізм доступу до даних за інтерфейсом.
13. Сервіс працює з IRepository, а реалізація з EF Core розташована в Infrastructure.
14. DbContext — контекст EF Core для запитів, відстеження змін і збереження; належить DAL.
15. SRP: кожен клас має окремий обов'язок; DIP: сервіс залежить від абстракцій.
16. Інтерфейси дозволяють підміняти реалізації та спрощують ізольовані тести.
17. Domain незалежний; Application та Infrastructure залежать від Domain; API підключає їх.
18. AddScoped реєструє репозиторії й сервіси; AddDbContext реєструє контекст БД.
19. Контролери мають бути тонкими: отримують DTO, викликають сервіси, повертають HTTP-коди.
20. Масштабування: додають функції в відповідні шари, оптимізують запити, використовують
    пагінацію та кешування; за потреби замінюють сховище чи виділяють окремі сервіси.
